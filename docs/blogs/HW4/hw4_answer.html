MaxDiff & Multinomial Logit
Which MSBA classes would students actually choose — if they had to?
Eesha Jagdhane  ·  May 25, 2026
← Back to Blogs & Insights

Introduction

Ask someone to rate ten MBA classes on a 1–10 scale and you get polite noise. Ask them to pick the one they want and the one they’d skip from a lineup of four — now you’re measuring something real. That’s MaxDiff (best–worst scaling): repeated forced choices instead of pretend precision.

Our “products” are the ten core MSBA classes at Rady. Each survey screen shows four; every pick is a miniature conjoint experiment. I take the class survey data and estimate preferences three ways — from a quick scoreboard to a full choice model — and see whether the story holds up:

  1. Counts — how often a class is picked best vs. worst when it appears on screen
  2. Multinomial logit (MLE) — a proper model of how people choose best and worst, with standard errors
  3. Bayesian MNL — the same model, but with a prior and MCMC so uncertainty is honest about shares, not just coefficients

The methods mostly agree on who’s on top and who’s at the bottom. The fun is in the middle — and in the interactive charts below (hover, zoom, and toggle where it helps).

Counts Analysis

Start with the scoreboard even your advisor could read in ten seconds. For each class \(j\), track how often it was picked best and worst when it appeared, then subtract:

\[ \text{score}_j = \%\text{best}_j - \%\text{worst}_j. \]

A score near +1 means “crowd favorite whenever it’s on the menu.” Near -1 means “please get this off my schedule.” Near 0 means fight night — the class is loved and hated in equal measure.

def bootstrap_counts(
    data: pd.DataFrame, B: int = 1000, seed: int = 495
) -> tuple[np.ndarray, pd.DataFrame]:
    """Return bootstrap draw matrix (B × 10) and CI table by Item."""
    rng = np.random.default_rng(seed)
    ids = data["record_id"].unique()
    items = np.arange(1, 11)
    mat = np.full((B, len(items)), np.nan)
    for b in range(B):
        samp = rng.choice(ids, size=len(ids), replace=True)
        d = data[data["record_id"].isin(samp)]
        sc = d.groupby("Item").agg(
            shown=("Response", "size"),
            best=("Response", lambda s: (s == 1).sum()),
            worst=("Response", lambda s: (s == -1).sum()),
        )
        sc["score"] = sc["best"] / sc["shown"] - sc["worst"] / sc["shown"]
        mat[b, :] = sc.reindex(items)["score"].to_numpy()
    ci = pd.DataFrame(
        {
            "Item": items,
            "ci_lo": np.quantile(mat, 0.025, axis=0),
            "ci_hi": np.quantile(mat, 0.975, axis=0),
        }
    )
    return mat, ci

From MaxDiff Data to MNL Choices

Counts are honest; they’re also wasteful. They ignore every time you didn’t pick a class. The multinomial logit (MNL) turns each MaxDiff screen into two statistical choices:

  1. Best choice from all \(J=4\) items on the screen, with utility \(\beta_j\) and probability
    \(P(\text{best}=b) = \exp(\beta_b) / \sum_{j \in \text{shown}} \exp(\beta_j)\).
  2. Worst choice from the three remaining items, with utilities negated:
    \(P(\text{worst}=c \mid \text{best}=b) = \exp(-\beta_c) / \sum_{j \neq b} \exp(-\beta_j)\).

One catch: utilities are only defined up to a constant. I pin \(\beta_1 = 0\) (MGTA 403 as the reference class) and estimate the other nine — standard move, same as setting the outside option to zero in class.

def build_tasks(df: pd.DataFrame) -> list[dict]:
    rows = []
    for _, g in df.groupby(["record_id", "Task"]):
        rows.append(
            {
                "items": g["Item"].astype(int).tolist(),
                "best": int(g.loc[g["Response"] == 1, "Item"].iloc[0]),
                "worst": int(g.loc[g["Response"] == -1, "Item"].iloc[0]),
            }
        )
    return rows

def prepare_task_arrays(task_rows: list[dict]) -> tuple[np.ndarray, np.ndarray, np.ndarray, np.ndarray]:
    """Precompute 0-based indices so each likelihood call avoids Python dict work."""
    n = len(task_rows)
    items = np.zeros((n, 4), dtype=np.int32)
    best = np.zeros(n, dtype=np.int32)
    worst = np.zeros(n, dtype=np.int32)
    rem = np.zeros((n, 3), dtype=np.int32)
    for i, row in enumerate(task_rows):
        it = np.asarray(row["items"], dtype=np.int32) - 1
        jb = row["best"] - 1
        items[i] = it
        best[i] = jb
        worst[i] = row["worst"] - 1
        rem[i] = it[it != jb]
    return items, best, worst, rem

MNL via Maximum Likelihood

Summing over all tasks, the log-likelihood is

\[ \ell(\boldsymbol{\beta}) = \sum_{\text{tasks}} \Big[ \beta_{j^*_b} - \log \sum_{j \in \text{shown}} e^{\beta_j} - \beta_{j^*_w} - \log \sum_{j \in \text{shown}\setminus\{j^*_b\}} e^{-\beta_j} \Big]. \]

I code the log-likelihood with logsumexp (so exp never explodes), then let scipy.optimize.minimize hunt for the peak. The interactive curve below is the week-5 “aha”: hold all other β’s at the MLE and slide β₉ (495) — hover along the curve to see the log-likelihood climb to its peak.

Show Python code 
def beta_full(b9: np.ndarray) -> np.ndarray:
    return np.concatenate([[0.0], np.asarray(b9, dtype=float)])


def log_likelihood(b9: np.ndarray) -> float:
    """Vectorized over all tasks (same math as the loop version)."""
    b = beta_full(b9)
    vb = b[TASK_ITEMS]
    best_part = b[TASK_BEST] - logsumexp(vb, axis=1)
    vw = -b[TASK_REM]
    worst_part = -b[TASK_WORST] - logsumexp(vw, axis=1)
    return (best_part + worst_part).sum()


mle_res = optimize.minimize(
    lambda x: -log_likelihood(x),
    np.zeros(9),
    method="BFGS",
)

b_hat = beta_full(mle_res.x)
se_free = np.sqrt(np.diag(mle_res.hess_inv))
se_full = np.concatenate([[0.0], se_free])
shares = np.exp(b_hat) / np.exp(b_hat).sum()

MNL via Bayesian Estimation

MLE gives a point. Bayes gives a cloud. The posterior is \(\pi(\boldsymbol{\beta} \mid \mathbf{y}) \propto L(\boldsymbol{\beta})\,\pi(\boldsymbol{\beta})\) with a gentle prior \(\boldsymbol{\beta} \sim N(\mathbf{0}, 10\mathbf{I})\) — wide enough to stay out of the way, tight enough to keep the sampler sane.

Show Python code 
def log_posterior(b9: np.ndarray) -> float:
    return log_likelihood(b9) + norm.logpdf(b9, loc=0, scale=np.sqrt(10)).sum()


def metropolis_hastings(
    beta0: np.ndarray,
    n_iter: int,
    step: float,
    seed: int = 495,
    label: str = "MCMC",
    progress_every: int = 2_000,
) -> tuple[np.ndarray, float]:
    rng = np.random.default_rng(seed)
    k = len(beta0)
    draws = np.empty((n_iter, k))
    beta = beta0.copy()
    lp = log_posterior(beta)
    accept = 0
    print(f"{label}: starting {n_iter:,} iterations...", flush=True)
    for t in range(n_iter):
        beta_star = beta + rng.normal(0, step, size=k)
        lp_star = log_posterior(beta_star)
        if np.log(rng.random()) < lp_star - lp:
            beta = beta_star
            lp = lp_star
            accept += 1
        draws[t] = beta
        if progress_every and (t + 1) % progress_every == 0:
            print(
                f"{label}: {t + 1:,} / {n_iter:,} — acceptance so far {accept / (t + 1):.3f}",
                flush=True,
            )
    return draws, accept / n_iter


# Tune step size toward 25–40% acceptance
step = 0.12
for trial_i in range(6):
    trial_draws, trial_acc = metropolis_hastings(
        mle_res.x, 3000, step, seed=495 + trial_i, label=f"Tuning trial {trial_i + 1}"
    )
    print(f"step = {step:.3f}, acceptance = {trial_acc:.3f}", flush=True)
    if 0.25 <= trial_acc <= 0.40:
        break
    step = step / 2 if trial_acc < 0.25 else step * 1.15

Discussion

If you’re choosing classes in this cohort, the market has spoken: take 495, load up on 453 / 455 / 452, and treat 444 as the option of last resort unless you love client-facing grind. The gap isn’t subtle — roughly 28% MNL share vs. 4% for consulting.

Statistically, this homework is really about three ways to listen to the same choices. Counts are the podcast summary; MLE is the transcript with footnotes; Bayes is the transcript plus a honest “we’re not 100% sure” margin on the quotes that matter (market shares).
